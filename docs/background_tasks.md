# 后台命令任务

后台任务属于启动它的会话，独立于单次模型运行。模型完成回复或停止生成不会自动停止已经交接给任务管理的命令。任务管理页、`task_stop` 和 Android 通知的停止入口均可停止任务及其子进程。任务结束后释放工作区引用和前台服务；删除会话、复制会话或卸载环境前必须先停止所属后台任务。

## 工具

- `shell` 原有同步执行行为保留。`background: true` 将命令交给任务管理并返回 `taskId`；`yieldMs` 设置最长等待窗口，未结束的命令继续运行并返回同一个任务 ID。`timeout` 仍是实际执行时限，与等待窗口独立。
- `task_list` 仅列出当前会话任务，支持 `activeOnly`、`offset`、`limit`。
- `task_output` 返回状态及分开的 stdout/stderr 日志。未提供位置时读取尾部；分别使用 `stdoutOffset`、`stderrOffset` 和对应 `nextOffset` 续读，`waitMs` 最长等待 30 秒且不取消任务。
- `task_stop` 仅停止当前会话中指定任务；已结束的任务返回已有状态，不重复发送命令。

持续服务应保持在前台，例如 `shell(command: "npm run dev", background: true)`。不要追加 `&`、`nohup` 或启用服务自守护模式：每项任务的原生监督进程仍在主进程退出、取消或宿主死亡时清理后代。后台化由应用任务管理负责。

## 生命周期与日志

同时最多 32 项活跃任务，每个会话最多 10 项。后台任务没有默认执行时限，也没有累计输出终止阈值。每路日志保留最新 256 KiB，旧字节被淘汰后，读取返回 `truncated` 和 `oldestOffset`；绝对字节位置不会因淘汰而归零。任务记录和有界日志存入加密数据库，流式日志批量提交，异常退出可能丢失最近尚未提交的日志。

应用进程重启会把尚未结束的任务标为 `interrupted`。不会自动恢复进程或重跑有副作用命令。用户可以在详情页明确重新运行，产生新的任务 ID；重新运行仍校验原有环境及工作区。

模型调用遵循现有权限规则：启动继承 `shell` 的命令确认，任务列表和日志为只读，停止是允许的控制操作但在计划模式中禁用。工具只接受当前会话所属任务，任务 ID 本身不授予跨会话访问。每次模型轮次前发布有界的任务状态分区，不把后台日志自动灌入上下文。

## 完成后续答

新任务默认开启 `notifyOnCompletion`：交接到后台后，成功、失败、执行超时以及用户停止均产生完成通知。空闲会话自动创建新的模型运行；忙碌会话在下一次模型请求前领取通知，即使模型已经给出本轮最终回答，仍会继续处理尚未领取的通知。同一步领取多个完成通知，通知只携带任务 ID 与终态，模型通过 `task_output` 读取所需日志。续答使用任务所属会话的助手、模型和当前权限，不切换正在查看的会话。

消息列表将后台续答接在任务来源的回答区后面，前提是中间没有新的用户消息或其他回答区。用户已发起新请求时，旧任务的续答按发生顺序独立展示。消息与运行记录仍各自保存，分组只影响界面；历史中缺少任务来源时保持独立展示。

等待工具已取得结束结果、模型通过 `task_output` 取得终态或模型自己调用 `task_stop` 时，不再发送重复通知。等待超时后仍在运行的任务，之后完成时仍会通知。控制器销毁及应用重启造成的中断不唤醒模型。旧版本创建的任务保持原来的仅保存结果行为。

完成状态与待领取标记一起落库，领取通知与追加宿主消息在同一事务提交。模型配置不可用或运行准备失败会保留待领取通知并显示重试入口；通知被运行领取后，模型请求失败按普通运行记录处理，不无限重试。用户停止 AI 回复后，所属会话的自动续答暂停，待领取通知保留，下一次用户发送或点击“继续 AI 回复”恢复。自动唤醒不设置次数上限；`notifyOnCompletion: false` 或创建表单的开关可让任务仅保存结果。

后台模式产物保留在会话工作区，通过文件工具读取；不会把持续服务的文件变化自动解释为某一次调用的产物附件。
